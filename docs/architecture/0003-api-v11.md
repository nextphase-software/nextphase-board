# 0003 — Server API contract

CONTRACT VERSION: 0003 API v11 (2026-11-10)

Status: Draft for 0007-W3 v1. Replaces [API v10](0003-api-v10.md).
All HTTP routes, authentication, origins, one-use tickets, capacity and lifecycle
ordering remain. POST /boards/:board/join-tickets and
GET /boards/:board/join?ticket=... still admit the authenticated room socket.
Joined additionally carries the recipient's spotlight projection from
[presence v3](0004-presence-v3.md), bounded separately from its document envelope.
The private presenter key is never in joined, a ticket, URL, directory or roster.

There is no spotlight HTTP route, roster endpoint, new socket, permission or
Supabase schema/deployment change. Issued tickets never promise later admission.
Fresh socket replay outage returns503 service_unavailable without joined state.
Each spotlight operation/publication and presenter relay uses live current
authority; no protected projection on denial/outage. Existing HTTP/cache,
operator-restore body/authentication and image refusal rules remain. No spotlight
field is accepted into the strict document/file/backup formats or restores.
Preserve original close/error cause through the worker entry and both adapters
before any WebSocket close-code normalization; presence v3 defines the policy.
Its spotlight_version_exhausted reason is returned unchanged in spotlight_refused
on the existing socket, with current projection only after current admission.
No new HTTP status/route or generic document refusal maps this condition; no
mutation retry. Both controlVersion and membershipVersion headroom rules use
this same refusal and never prevent mandatory terminal cleanup. Existing room
socket now recognizes recoverable client close4410/retry_recovery per sync v12;
clean departures and terminal4401/4403/4409/4423 retain their separate policies.
