# 0003 — Server API contract

CONTRACT VERSION: 0003 API v8 (2026-11-07)

Status: Draft for 0006-W4 v1. Replaces [API v7](0003-api-v7.md), keeping all ordinary and
five history routes/shapes except the explicit lifecycle gate below. Replaces its no-Trash
route exclusion. Partners: [lifecycle v2](0006-board-lifecycle-v2.md),
[access v8](0003-access-v8.md), [persistence v8](0003-hosted-persistence-v8.md).
Both runners expose identical current routes. Existing body ceilings remain; lifecycle bodies
are also at most **65,536 UTF-8 bytes**, then 413 body_too_large. Unknown keys/types are 400
bad_request. UUIDs are lowercase; cycle/generation/time values are nonnegative safe integers.

## Gates and response order

Verify bearer first: invalid authentication 401. Malformed/missing IDs or signed-in callers
without identifiable current access get generic 404 not_found. Ordinary protected routes,
including the five history routes and accepted-request result resolution, next require active
authority/no deleted marker. Otherwise generic 404 without title/content/count/deadline/state.
Apply this before room creation/load, export, rename, participant/notification data and retries.
Join/old tickets use generic 401 ticket_invalid; connected peers close 4403. Outage/unreadable
required authority remains retryable 503 service_unavailable and yields no cached success.
Operator authenticated recovery/backup routes also refuse non-active/deleted IDs with generic
404; operator authentication/size/schema rules still apply, without revival.

Lifecycle routes below are a separate surface. Recheck current workspace ownership before any
Trash metadata/result. An identifiable caller with current workspace membership or board access
but insufficient lifecycle rights gets 403 role_too_low, needed owner, without lifecycle data.
An outsider/disabled caller gets generic 404. These checks apply even to completed receipts and
pending retries. In a workspace-qualified route the board must belong to that workspace, never
a cross-workspace count/title/status oracle. Successful directory reads are not document access.

The inherited `DELETE /boards/:board/grants/:person` is the sole unavailable-board grant
administration exception to the active-only gate. For moving/trashed/restoring, authorize the
current workspace owner directly from lifecycle/retained board identity, not board_role; SQL
rechecks ownership and state atomically as access v8 specifies. Return the inherited 200
{boardId,personId,removal}, with no protected metadata; no body/new route is added. Preserve
401 first, identifiable non-owner 403 role_too_low/needed owner, outsider/disabled/missing/
purging/deleted 404 and source failure 503. PUT grants and invitation acceptance stay active-only.
This exception never opens/initializes a room; denied content/history routes remain generic 404.

## Routes and exact shapes

| Method/path | Query/body | Success |
| --- | --- | --- |
| GET /boards/:board/lifecycle | None; current owner, active board only | 200 {boardId,workspaceId,state:"active",cycle,generation} |
| GET /workspaces/:workspace/trash | optional cursor only | 200 {boards:[TrashRow],nextCursor} |
| POST /boards/:board/trash | {requestId,expectedCycle} | 200 OperationResult after fully confirmed move; 202 OperationResult when accepted/pending |
| POST /workspaces/:workspace/trash/:board/restore | {requestId,expectedCycle} | 200 OperationResult after fully active; 202 OperationResult when accepted/pending |
| POST /workspaces/:workspace/trash/:board/delete | {requestId,expectedCycle} | 200 OperationResult after confirmed purge; 202 OperationResult when accepted/pending |
| GET /workspaces/:workspace/trash/:board/status | None | 200 OperationResult for current lifecycle or deleted marker |

Move first reads owner-only GET lifecycle so its confirmation uses a current cycle; the returned
generation is informational, not a replacement expected document head. Restore/delete use the
cycle in the real Trash row. requestId is a once-generated UUID. POST bodies contain exactly
the listed keys, never title/document/deletion time/actor/permissions. GET has no body. Unknown
query keys on every route are bad_request. Do not call these routes for local/team-off boards.

TrashRow is one of:
- {boardId,workspaceId,state:"trashed",cycle,generation,title,deletedAt,restoreBefore};
- {boardId,workspaceId,state:"moving"|"restoring"|"purging",cycle,generation}.

On reload moving/restoring use their own Moving to trash… / Restoring… labels and Refresh
status only, as hosted storage v8/interaction v34 specify. Their metadata comes solely from
this current-owner-authorized list shape: no title/deletion times are supplied, so none are
rendered or recovered from disk/status dates. A status GET confirms progress; refetch this list
to obtain any newly available authorized row metadata.

The first retains authorized pre-purge metadata; at logical expiry it can still appear until the
irreversible purge transition, with Restore disabled. Once purging, only the second content-free
shape is allowed. title follows the existing 120-code-point directory-title rule. Dates use server
Unix milliseconds. Deleted markers and active/restored receipts are not list entries. List pages
contain at most **50** rows ordered deletedAt descending then boardId ascending; non-Trash pending
rows sort first by boardId. nextCursor is null or an opaque validated continuation bound to the
workspace and ordering keys (at most **512 ASCII bytes**); malformed/foreign-workspace cursor is
400 bad_request; no counts or other workspaces.
The client reads all pages, deduplicating boardId and discarding obsolete responses.

OperationResult is exactly {boardId,workspaceId,state,cycle,generation,deletedAt,restoreBefore}.
state is active/moving/trashed/restoring/purging/deleted. Dates are non-null only for moving/trashed/
restoring; null for active/purging/deleted. For deleted, cycle is null (register has no cycle),
generation is the register generation. No title, person, document or receipt body in this result.
Every accepted-operation retry also returns current authoritative cycle state, not a stale phase.
Status for a board active after Trash restore allows the owner to resolve a lost restore answer;
a missing board with no authority/register is 404, never inferred deleted. Unknown GET status
never creates a lifecycle record. Owner-only deleted status authorizes via the register's workspace ID.

## Conflicts, failures and retry

After auth/role and envelope validation resolve same accepted request, then apply new-operation
preconditions. Same identity/different body/operation: 409 request_id_reused. Wrong/stale cycle:
409 lifecycle_changed. Restore at/after deadline or purge winner: 409 trash_expired. Competing
nonterminal operation: 503 lifecycle_pending; previously accepted history restore: 503 restore_pending
before Move admission. A fully known pre-admission move/restore rollback is 503 move_failed or
restore_failed respectively. Use those only when unchanged state is proven; all other failures
are uncertain. A durable pending operation normally returns 202 with its actual state; a lost
answer/required-service failure can be 503 service_unavailable, never a false rolled-back success.
A current-owner delete/status of a permanently deleted ID resolves the register as deleted without
recreating requests or room state. An old operation cannot act on a new cycle.

An explicit browser Retry repeats the identical method/path/body/requestId; status Refresh is GET.
Server automatic continuation uses the existing persisted identity/phase. Reads never silently
submit a new mutation. Home remains #/files, workspace #/files/<workspaceId>, board #/b/<boardId>.
Trash uses #/files/<workspaceId>/trash. No shared version URL, new asset route or export is added.
