## Lifecycle ending

Read active authority/no deleted marker before creating/loading a room, consuming a join ticket,
joining, answering receipts, accepting/retrying/queueing/applying an edit/comment, capture,
participant/presence publication, export and recovery. Recheck the admitted lifecycle generation
at the ordered write/receipt boundary, not only on initial HTTP authorization. Fail closed on
unreadable authority. A durable moving/purging fence makes held work permanently ineligible;
no old saved/received receipt implies permission to apply it. Current history receipt resolution
also follows this rule. No new joined or edit-envelope field is added for history-expiry copy.
The restored confirmation uses neutral wording without inferring when versions expired.

Freeze captures, invalidate tickets/waiting and end connected peers with **4403** before exposing
trashed success. Generic ticket refusal remains **401 ticket_invalid**. Do not disclose deletion
actor, title, deadline, count or lifecycle state through the ordinary ending. A missing close
hint or dropped socket cannot bypass server gates. An unavailable required service is retryable
503; it cannot authorize a cached join or save.

## 4403: reauthorize before classifying the ending

4403 alone is not final-loss evidence: access role/epoch changes, including editor→viewer,
also use it. Immediately pause writes/comment sends and invalidate held response epochs, then
perform fresh authenticated board authorization/ticket acquisition. Pending authorization may
hide protected paint but keeps tab-memory unposted text/ranges; do not label the board deleted,
terminally clear drafts or navigate Home solely from the close code. A successful fresh ticket
and joined snapshot re-establish current active lifecycle/access and the new role/epoch. Reconnect
under that role, keep unposted drafts for explicit review, revalidate pending work against current
rights/epoch and never auto-send comments or rewrite old immutable requests as new authorized
work. Viewer controls remain read-only; this path adds no permission. Preserve the existing
mentions.test.mjs M-U14 reconnect/draft assertions unchanged.

A current-board authorization/ticket 404 not_found (not a selected-version 404), or a confirmed
authorized lifecycle transition proving unavailability, is terminal. On a 503/unreadable required
source, remain paused/unconfirmed with drafts only in tab memory and explicit retry; no cached
access, new save or false terminal claim. A generic ticket_invalid alone calls for fresh ticket
authorization, not proof of deletion. Account/sign-out/invalid-auth boundaries still clear
protected state through the existing auth flow. A later lifecycle denial overrides any earlier
successful role reauthorization; no delayed result can repaint or reconnect a terminal session.

Only confirmed unavailability after 4403 clears all protected browser state: live/preview canvas/title, selection/context/tools,
History/Comments/dialogs, inbox previews, Undo/Redo, unposted protected drafts/ranges, outstanding
edits/comment retries and delayed response handlers. Focus the generic ending, show Returning
to Home…, then #/files with the generic status. Do not automatically rejoin or resend. A later
explicit Open board after Trash restore obtains fresh access, ticket and joined generation.
Old tickets/work remain invalid even though the board ID is the same.

History document restore still uses **4423**, preserves tab drafts for explicit review and
rejoins under v8. Trash restore changes availability, not the document; it creates neither a
history replacement nor a 4423 reconnect of the closed tab. Its higher generation blocks all
pre-Trash work. A new deliberate edit/comment after fresh opening works under current access.
