Status: Draft for 0006-W3 v1. Replaces [sync v7](0003-sync-v7.md), retaining its current
comment ranges, immutable retries, deadlines, presence and frame limits. Current storage is
[hosted persistence v7](0003-hosted-persistence-v7.md), discussion [comments v3](0005-comments-v3.md).

## Edit generation fence

The current `edit` envelope is exactly `{kind:"edit",epoch,requestId,update,restoreGeneration}`.
`restoreGeneration` is a nonnegative safe integer captured from joined. Serialize it once with
the update/request ID/epoch; ordinary retransmission preserves it byte for byte. Comment
operations keep v7's generation field/check order. A malformed envelope is `bad_message`.

After effective access/epoch and editor-role validation, compare edit restoreGeneration with the
live room generation **before** decoding/retrieving a receipt, answering received/saved, admitting
waiting work, or applying/retrying it. A mismatch answers `refused` with `reason:"restore_changed"`,
saving nothing. Never return an old saved receipt as permission to apply stale work. Clear
waiting work and tickets at restore; replay must carry and recheck captured generation.
Current edit receipts/digests keep their existing meaning within one generation. New edits
capture the new joined generation. No recovery crosses the restore fence.

## Document-restore ending

Both user history restore and operator whole-room restore use 4423. Before a user-history close,
send `{kind:"history_restoring",actor}` to connected peers, where actor is the authorized
restorer's board label snapshot. This is a display hint only; the generation in the subsequent
joined is authoritative. Losing the hint cannot permit stale work. Rejoin uses fresh Yjs state;
a changed joined generation drops outstanding edits with the existing `board_restored` loss
classification, blocks explicit old comment retry, clears board Undo/Redo and ends following.
Superseded requests are terminal and never automatically resent. Preserve unposted comment
text/ranges in tab memory for explicit review under hosted storage v7. Service lock during
rejoin stays restoring; do not claim connected/Saved until a valid joined snapshot arrives.
Read-only previews are HTTP documents and never enter BoardSession's live editing CRDT.
