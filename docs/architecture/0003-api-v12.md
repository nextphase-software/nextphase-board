# 0003 — Server API contract

CONTRACT VERSION: 0003 API v12 (2026-11-14)

Status: Draft for 0008-W2 v1. Replaces [API v11](0003-api-v11.md), whose routes, authentication,
origins, tickets, capacity, lifecycle ordering, socket rules and error bodies remain word for word.
[Team templates v1](0008-team-templates-v1.md) adds five authenticated JSON routes, registered in
`apps/server/src/app.ts` from a new `apps/server/src/routes/templates.ts`, so the Cloudflare Worker
and the Node runner serve them identically. They are not under `/boards/:board/*`, so the board
lifecycle gate does not run first; the save and replace functions check the source board instead.

A **template** in a response is exactly:
`{id, name, description, creatorLabel, sourceTitle, objectCount, createdAt, updatedAt, canManage, objects}`
(times as ISO 8601 UTC strings with milliseconds; `objects` as stored).

| Route | Body (exact keys) | Success | Refusals |
| --- | --- | --- | --- |
| `GET /workspaces/:workspace/templates` | — | 200 `{templates: [template…], limit: 25, canSave}`, newest `updatedAt` first | 404 `not_found` (no membership, disabled, unknown workspace); 403 `role_too_low`, `needed: "viewer"` (guest) |
| `GET /workspaces/:workspace/templates/:template` | — | 200 template | as the list; also 404 for an unknown template or one of another workspace |
| `POST /workspaces/:workspace/templates` | `{name, description, sourceBoard, objects}` | 201 template | 400 `bad_request` (shape, name, description, a `sourceBoard` that is not a lowercase UUID, objects); 413 `template_too_large` (`content_bytes` > 262,144); 413 `body_too_large`; 404 `not_found` (workspace as the list; a `sourceBoard` that is unknown, not active, of another workspace or on which the caller has no role); 403 `role_too_low`, `needed: "viewer"` (guest), `needed: "editor"` (workspace viewer, or a board role of viewer); 409 `template_limit` |
| `PATCH /workspaces/:workspace/templates/:template` | either `{name, description}` or `{sourceBoard, objects}` | 200 template | 400/413 as POST for the matching form; then, in this order: 404 (workspace as the list) or 403 `needed: "viewer"` (guest); 404 for an unknown template or one of another workspace; 403 `needed: "owner"` without the manage right (this covers a creator who is now a viewer); for `{sourceBoard, objects}` only, the source board as POST: 404, or 403 `needed: "editor"` for a board role of viewer |
| `DELETE /workspaces/:workspace/templates/:template` | — | 204, empty body | in the PATCH order: 404 or 403 `needed: "viewer"`; 404 for the template; 403 `needed: "owner"` |

Checks run in this order: path ids (lowercase UUIDs by `id()` in `routes/common.ts`, else 404),
body size, JSON and exact keys, field values (400 or 413), then the database function (404, 403,
409). The `needed` field is exactly as listed. `name` and `description`
are strings; `sourceBoard` a UUID string; `objects` an array. Error bodies use the existing
`errorBody` shape. A database outage is 503 `service_unavailable` and changes nothing. Responses
carry the same CORS and caching headers as the existing list routes. No other route, socket frame,
ticket or joined field changes.
