## Recoverable client close versus explicit ending

This version supersedes sync v5's Ending an attempt / Progress deadline wire
close(1000) requirement only for recoverable paths. BoardSession.endAttempt must
receive an explicit close classification; a nonterminal path that will retry sends
transport.close(4410, "retry_recovery"), including send throw, progress deadline,
recoverable interrupt/reconnect and hosted offline/retry cleanup. Extend the
Transport close type/hosted WebSocket adapter to close(code:number,reason?:string).
Audit every caller, including rejoin/abandoned attempts and terminal discard,
unavailable and close; do not infer retry solely from the absence of an event.
Abandoned sockets that never joined have no spotlight to resume; if still part
of an ongoing recoverable attempt use4410, while explicit terminal abandonment
stays clean. HostedBoard.finish's retry branch and offline path must use the
same4410/retry_recovery rather than a later unconditional close(1000).

Preserve local SessionEvent semantics: deadline still reports exactly
{kind:"close",code:4000,reason:"answer_deadline"}; send failure still reports1006;
interrupt remains silent and actual transport-close events retain their actual
code.4410 is a retryable transport outcome, not an access failure. No edit
request ID, bytes, waiting count/order, ten-second deadline, deduplication,
Undo/Yjs rejoin fence or authority rule changes. Terminal access/generation/
expiry/conflict4403/4423/4401/4409 always override grace/retry classification.
Refusal-driven access reauthorization is terminal for old spotlight authority,
regardless of a later fresh document rejoin. Explicit navigation/leave/sign-out/
BoardSession.close/terminal discard remain clean1000 (tab close may be1001),
and explicit Stop invalidates spotlight before any subsequent recovery close.
Both runner adapters forward original code/reason into presence v3's exact
Room.closed signature; no-close-frame1006/missing Node code remains abnormal.
