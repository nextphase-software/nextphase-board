# 0003 — Room sync contract

CONTRACT VERSION: 0003 sync v7 (2026-11-05)

Status: Draft for 0005-W2 v1. Replaces [sync v6](0003-sync-v6.md).
V6's room order, edit/recovery paths, comment snapshot, broadcasts, receipt namespace,
request states, deadlines, size limits and close codes apply except for these additions.
[Comments v2](0005-comments-v2.md) supplies ranges, validation order and lifecycle;
[hosted persistence v6](0003-hosted-persistence-v6.md) supplies storage and projection.
This specifies the current client/server protocol only; no mixed-version negotiation is needed.

## Comment operations and frames

The `comment` envelope includes integer `restoreGeneration`, captured from `joined`, alongside
`epoch`, `requestId` and `operation`. `start`, `reply` and `edit` operations accept `mentions`
(comments v2); omission means `[]`, explicit `null` is invalid. Other actions do not carry ranges.
Every current `comment_changed.comment` includes `mentions`, including snapshot and retry frames.
Thread fields, broadcast-before-ack order and the snapshot's reset/rows/done order are unchanged.
Neither board `revision` nor edit receipts/recovery/Undo change.

The room uses comments v2's check order. Additional `comment_refused.reason` values are
`mention_limit`, `bad_mentions`, `mention_unavailable`, `mention_pending_limit` and
`restore_changed`. They do not cause edit recovery or a rejoin. There is no capability query,
legacy projection or upgrade-required refusal in this protocol.

## Immutable retries

`BoardSession` normalizes text and serializes the whole message **once**, keeping the exact
operation object/key order, ranges, epoch, request ID and restore generation. The receipt digest
remains SHA-256 of UTF-8 `comment:` followed by `JSON.stringify` of the parsed operation.
A retry sends exactly the stored message, never a newly resolved label or a mutable array.
Access/epoch and restore generation are checked before the receipt. Reusing a request ID with
another digest or another receipt kind is `request_id_reused`.

V6's explicit `retryComment` gates remain: `join_required`, `not_retryable`, then
`access_changed` if the captured epoch/generation no longer matches. The client never queues or
resends comments automatically. Saved/refused requests are terminal. Losing an answer leaves
`unconfirmed`, with the draft and ranges retained. Delivery retry is a server responsibility
and cannot duplicate the saved comment or its notice after a lost acknowledgement.

## Size

One frame/request stays below the existing 1,048,576-byte transport limit. The maximum legal
4,000-code-point text plus 20 ranges at 256-byte labels is measured as actual serialized UTF-8;
assert all 20 exact stamped ranges are present, so a server ignoring metadata cannot pass on
size alone. No assumption that every Unicode character is one byte. Metadata is separate from board edits.
