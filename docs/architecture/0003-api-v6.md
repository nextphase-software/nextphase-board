# 0003 — Server API contract

CONTRACT VERSION: 0003 API v6 (2026-11-05)

Status: Draft for 0005-W2 v1. Replaces [API v5](0003-api-v5.md).
V5's existing routes, creation/import checks and refusals apply unchanged, except earlier-version
client/document/file conversion is outside this milestone. Current-format imports still work.
New routes use [identity v4](0003-identity-v4.md), [access v6](0003-access-v6.md),
[comments v2](0005-comments-v2.md) and [hosted persistence v6](0003-hosted-persistence-v6.md).
Both Node and Workers expose the same routes. No new comment-write HTTP route is added.

## Common rules and routes

Verify the bearer token first, before IDs or lookups. Board and notice IDs are lowercase UUIDs.
Malformed IDs and missing/denied targets answer 404 `not_found`. Invalid query/body is
400 `bad_request`. Supabase/room read or write failure is 503 `service_unavailable`, with no
cached preview or false success. Body limits stay 1,048,576 bytes, except creation's
13,631,488 and operator restore's 16,777,216. Over-limit bodies are 413 `body_too_large`.

| Method/path | Query or exact body | Success |
| --- | --- | --- |
| `GET /boards/:board/participants` | `q` default `""`, at most 4,000 UTF-16 code units; `page` default 0, nonnegative safe integer | 200 `{candidates:[{person,label,suffix}],more}`; 20 rows/page |
| `GET /notifications` | None | 200 `{notices:[{id,version,read,createdAt,boardId,title,threadId,comment,anchor,resolved,workspace}]}`; at most 50 |
| `GET /notifications/:notice/open` | None | 200 `{boardId,title,threadId,comment,anchor,resolved}`; no read side effect |
| `POST /notifications/actions` | `{action:"read"\|"unread"\|"dismiss",seen:[{id,version}]}`; at most 50 entries | 204 after confirmed action |
| `POST /boards/:board/mentions/displayed` | `{comments:[<comment UUID>]}`; at most 2,000 | 204 after revalidation and marking the caller's references read |

`version` is a nonnegative safe integer from `state_version`; action entries have exactly
`id,version`. `comment` is the whole current public comment record (comments v2), never an
account UUID. `workspace` is the accessible workspace's name; for a board-only guest unable to
list that workspace it is `Workspace`. `anchor` and `resolved` are the current thread's values.
There is no participant email query, directory beyond the board, invite action or older inbox page.
The ticket route has no mention capability query or negotiation; current connections use sync v7.

## Participants

After token and board ID, authorize effective board access, validate query, then query the
service-only permitted roster. Use identity v4's labels/keys/suffixes. Search case-insensitive
label substring, sort label then person key, return 20 from the requested page and `more` if
another page exists. Guest peers are excluded before search/paging. Return no account, email,
lease or disabled/pending person data. A new target is checked again at comment-save time.

## Live previews and open

List only the account's retained accessible current-lease references. For each, replay access
and check the live room's restore fence, occurrence and comment **before** reading title, author
or text into the response. Resolve board/workspace labels only after that check.
Omit and dismiss stale deleted/denied references. Any service failure instead fails the request
with 503 and keeps the valid reference; never treat it as denial, an empty list or a partial
current list. Home does not scan the board directory to assemble previews.

Opening finds the ID only within that account's retained references, rechecks access and the
live target and returns its current context. Foreign, absent, removed and denied references all
answer the same generic 404 with no title/author/text. A failed service read returns 503 and
keeps the reference. The web app, after successful explicit navigation and display, marks the
actually visible comments through the displayed route.

## Explicit account actions

Read/unread compare-and-set **each supplied row's version**; increment state version on a saved
change. An obsolete version is a no-op, not an overwrite of another browser's newer action.
Dismiss is idempotent and removes only the caller's reference. Missing/foreign IDs are no-ops,
with the same 204. Mark all is an ordinary `read` action with the retained ID/version snapshot
seen by that request: a concurrently arriving notice stays unread. After confirmation the tab
fetches canonical state; it never assumes a late CAS won. A failed refresh offers Retry for the
read, without replaying a confirmed action.

Displayed marking authorizes the board and validates the body; finds only the caller's retained
references for those comment IDs; revalidates every live target before calling the service
read action. The UI sends IDs only for fully visible comment rows after an explicit thread/notice
open. Merely opening Home, Notifications or Comments marks none.

No automatic browser retries for inbox writes. An unconfirmed action retains its immutable
body in memory for explicit Retry; it never reports read/dismissed until confirmation.
